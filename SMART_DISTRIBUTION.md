# Умное распределение обещаний между ценностями

## Проблема

При импорте из Excel одно и то же корневое обещание могло встречаться в нескольких ценностях. Ранее парсер просто оставлял обещание в первой встретившейся ценности, что могло приводить к несбалансированному распределению.

## Решение

Парсер теперь использует **умную логику распределения**:

1. **Если обещание встречается впервые** - добавляется в текущую ценность
2. **Если обещание уже есть в другой ценности** - сравнивается количество обещаний:
   - Если в текущей ценности **меньше** обещаний → обещание **перемещается** в неё
   - Если количество **одинаковое** → обещание **остаётся** в старой ценности
   - Если в текущей ценности **больше** обещаний → обещание **остаётся** в старой ценности

## Логика работы

### Пример 1: Перемещение в ценность с меньшим количеством обещаний

```
Excel:
Ценность A (3 обещания) | Обещание X | ...
Ценность B (1 обещание) | Обещание X | ...  ← Дубликат

Результат:
- Обещание X создаётся при первом появлении (в ценности A)
- При втором появлении (в ценности B) парсер сравнивает:
  - Ценность A: 3 обещания
  - Ценность B: 1 обещание
- 1 < 3, поэтому обещание X перемещается в ценность B
- Итог: Ценность A (2 обещания), Ценность B (2 обещания)
```

### Пример 2: Оставление при одинаковом количестве

```
Excel:
Ценность A (2 обещания) | Обещание X | ...
Ценность B (2 обещания) | Обещание X | ...  ← Дубликат

Результат:
- Обещание X создаётся при первом появлении (в ценности A)
- При втором появлении (в ценности B) парсер сравнивает:
  - Ценность A: 2 обещания
  - Ценность B: 2 обещания
- 2 == 2, поэтому обещание X остаётся в ценности A
- Итог: Ценность A (2 обещания), Ценность B (2 обещания)
```

### Пример 3: Оставление при большем количестве в текущей

```
Excel:
Ценность A (1 обещание) | Обещание X | ...
Ценность B (3 обещания) | Обещание X | ...  ← Дубликат

Результат:
- Обещание X создаётся при первом появлении (в ценности A)
- При втором появлении (в ценности B) парсер сравнивает:
  - Ценность A: 1 обещание
  - Ценность B: 3 обещания
- 3 > 1, поэтому обещание X остаётся в ценности A
- Итог: Ценность A (1 обещание), Ценность B (3 обещания)
```

## Реализация

### Отслеживание принадлежности обещаний

```typescript
// Отслеживаем, в какой ценности находится каждое корневое обещание
const rootToValue = new Map<string, string>(); // rootTitle -> valueName
```

### Логика перемещения

```typescript
if (!root) {
  // Создаём новое обещание
  root = { ... };
  rootsMap.set(rootTitle, root);
  value.promises.push(root);
  rootToValue.set(rootTitle, valueName);
} else {
  // Обещание уже существует
  const existingValueName = rootToValue.get(rootTitle);
  
  if (existingValueName && existingValueName !== valueName) {
    const existingValue = valuesMap.get(existingValueName);
    
    if (existingValue) {
      const existingCount = existingValue.promises.length;
      const currentCount = value.promises.length;
      
      // Если в текущей ценности меньше обещаний - перемещаем
      if (currentCount < existingCount) {
        // Удаляем из старой ценности
        existingValue.promises = existingValue.promises.filter(p => p.id !== root!.id);
        
        // Добавляем в текущую ценность
        value.promises.push(root);
        rootToValue.set(rootTitle, valueName);
        
        warnings.push(`Обещание "${rootTitle}" перемещено из "${existingValueName}" (${existingCount}) в "${valueName}" (${currentCount + 1})`);
      } else {
        // Оставляем в старой ценности
        warnings.push(`Обещание "${rootTitle}" оставлено в "${existingValueName}"`);
      }
    }
  }
}
```

## Преимущества

### 1. Сбалансированное распределение
Обещания автоматически распределяются так, чтобы количество обещаний в ценностях было максимально равномерным.

### 2. Прозрачность
Все решения парсера логируются в массив `warnings`, что позволяет отследить, почему обещание было перемещено или оставлено.

### 3. Предсказуемость
Логика проста и понятна:
- Меньше обещаний → переместить
- Одинаково → оставить
- Больше → оставить

### 4. Гибкость
Если нужно изменить логику распределения, достаточно изменить одно условие в коде.

Для проверки логики распределения:

1. **Подготовьте Excel файл** с дублирующимися обещаниями в разных ценностях
2. **Импортируйте файл** через админ-панель
3. **Проверьте предупреждения** в интерфейсе импорта
4. **Проверьте результат** - обещания должны быть распределены сбалансированно

### Тестовый сценарий

```
Excel:
Ценность A | Обещание 1 | ...
Ценность A | Обещание 2 | ...
Ценность A | Обещание 3 | ...
Ценность B | Обещание 2 | ...  ← Дубликат
Ценность B | Обещание 4 | ...

Ожидаемый результат:
- Обещание 2 перемещается из A в B
- Ценность A: 2 обещания (1, 3)
- Ценность B: 3 обещания (2, 4)
```

## Производительность

- Отслеживание принадлежности: O(1) благодаря Map
- Сравнение количества: O(1)
- Перемещение обещания: O(n), где n - количество обещаний в ценности
- Общая сложность: O(n * m), где n - количество строк, m - среднее количество обещаний в ценности
- Минимальное влияние на производительность
