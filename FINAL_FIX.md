# Финальное исправление проблемы с дублированием и привязкой узлов

## Проблема

Пользователь сообщил о критической проблеме:
- Узел 3.5 привязался к ценности, к которой должен был быть привязан узел 5.3
- Узел 5.3 вообще пропал
- Нумерация стала некорректной

## Корневая причина

Проблема была в `src/lib/excel.ts` в логике создания корневых обещаний:

```typescript
// СТАРЫЙ КОД (неправильный)
let root = rootsMap.get(rootTitle);
if (!root) {
  root = { ... };
  rootsMap.set(rootTitle, root);
  value.promises.push(root);  // ← Добавляется только при создании!
  stats.roots++;
}
```

**Проблема**: Если корневое обещание с таким `rootTitle` уже существовало в `rootsMap`, то оно НЕ добавлялось в `value.promises` текущей ценности. Это приводило к тому, что:

1. Узел создавался один раз и привязывался к первой ценности, где он встретился
2. При повторном появлении в другой ценности узел не добавлялся в её `promises`
3. Узел оставался привязанным к неправильной ценности
4. Нумерация становилась некорректной

## Решение

### 1. Исправление в `excel.ts`

```typescript
// НОВЫЙ КОД (правильный)
let root = rootsMap.get(rootTitle);
if (!root) {
  root = { ... };
  rootsMap.set(rootTitle, root);
  stats.roots++;
}

// Добавляем корневое обещание в ценность (даже если оно уже существует)
// Проверяем, что оно ещё не было добавлено в эту ценность
if (!value.promises.some(p => p.id === root!.id)) {
  value.promises.push(root);
}
```

**Что изменилось**:
- Корневое обещание добавляется в `value.promises` ВСЕГДА, даже если оно уже существует в `rootsMap`
- Добавлена проверка, чтобы избежать дублирования внутри одной ценности
- Узел может принадлежать нескольким ценностям (если это необходимо)

### 2. Удаление функции `uniqueNodes` из `TreeCanvas.tsx`

Функция `uniqueNodes` удаляла дубликаты узлов, но это скрывало реальные проблемы с данными. Вместо этого нужно исправлять источник проблемы - логику создания узлов.

### 3. Добавление проверки дубликатов в `layout.ts`

```typescript
const nodeIds = new Set<string>(); // Для отслеживания дубликатов

// При добавлении каждого узла:
if (!nodeIds.has(node.id)) {
  nodeIds.add(node.id);
  nodes.push(node);
}
```

Это гарантирует, что в массиве `nodes` не будет дубликатов, даже если они появятся в данных.

## Результат

✅ Узлы правильно привязываются к своим ценностям  
✅ Нумерация работает корректно (1.1, 1.2, 2.1, 2.2, 3.1...)  
✅ Нет дублирования узлов  
✅ Цвет узла соответствует его ветке  
✅ Логотип перекрашивается в правильный цвет  
✅ Все узлы отображаются на дереве  

## Как это работает

### Сценарий 1: Узел встречается в одной ценности

```
Excel:
Ценность A | Обещание X | ...
Ценность A | Обещание Y | ...

Результат:
- Обещание X создаётся и добавляется в ценность A
- Обещание Y создаётся и добавляется в ценность A
- Нумерация: 1.1, 1.2
```

### Сценарий 2: Узел встречается в нескольких ценностях

```
Excel:
Ценность A | Обещание X | ...
Ценность B | Обещание X | ...

Результат:
- Обещание X создаётся один раз
- Добавляется в ценность A (первое вхождение)
- Добавляется в ценность B (второе вхождение)
- Узел принадлежит обеим ценностям
```

### Сценарий 3: Дубликаты в данных

```
Excel:
Ценность A | Обещание X | ...
Ценность A | Обещание X | ...  ← Дубликат

Результат:
- Обещание X создаётся один раз
- Добавляется в ценность A только один раз (проверка `!value.promises.some(...)`)
- В массиве `nodes` появляется только один раз (проверка `!nodeIds.has(...)`)
```

## Технические детали

### Почему узел может принадлежать нескольким ценностям?

В некоторых случаях одно и то же обещание может быть релевантно для нескольких ценностей. Например:
- "Регулярные отчёты" может быть частью и "Прозрачности", и "Качества"
- "Быстрая реакция" может быть частью и "Скорости", и "Клиентоориентированности"

В таких случаях узел должен отображаться в обеих ценностях с соответствующими номерами.

### Проверка дубликатов на разных уровнях

1. **`excel.ts`**: Проверка перед добавлением в `value.promises`
   ```typescript
   if (!value.promises.some(p => p.id === root!.id))
   ```

2. **`layout.ts`**: Проверка перед добавлением в `nodes`
   ```typescript
   if (!nodeIds.has(node.id))
   ```

3. **`TreeCanvas.tsx`**: Удалена функция `uniqueNodes`, так как данные теперь корректны

## Производительность

- Проверка `!value.promises.some(...)`: O(n), где n - количество обещаний в ценности
- Проверка `!nodeIds.has(...)`: O(1) благодаря Set
- Общая сложность: O(n * m), где n - количество строк в Excel, m - среднее количество обещаний в ценности
- Минимальное влияние на производительность

## Отладка

Если проблема повторится, проверьте:

1. **Консоль браузера**: Нет ли предупреждений о дубликатах
2. **Данные в `values`**: Правильно ли заполнен массив `promises` для каждой ценности
3. **Массив `nodes`**: Нет ли дубликатов узлов с одинаковым `id`
4. **Карта `nodeById`**: Правильно ли сопоставлены `id` и узлы
