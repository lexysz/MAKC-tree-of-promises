# Исправление проблемы с дублированием узлов

## Проблема

Узел 3.5 появлялся дважды:
1. После 3.4 (правильно) - с правильным цветом ветки
2. После 5.2 (неправильно) - с неправильным цветом ветки

Это приводило к тому, что узел отображался дважды с разными цветами, что нарушало визуальную целостность дерева.

## Причина проблемы

Проблема возникала из-за того, что в массиве `nodes` могли присутствовать дубликаты узлов с одинаковым `id`, но разными свойствами (например, разным `color`).

Когда мы создавали карту `nodeById` с помощью:
```typescript
nodeById.current = new Map(nodes.map((n) => [n.id, n]));
```

Map автоматически перезаписывал значения при наличии дубликатов ключей, что могло приводить к непредсказуемому поведению.

Кроме того, при рендеринге узлов:
```typescript
{nodes.map((nd) => (
  <NodeGlyph key={nd.id} node={nd} ... />
))}
```

React мог рендерить один и тот же узел дважды, если он присутствовал в массиве несколько раз.

## Решение

### 1. Удаление дубликатов узлов

Добавлена функция `uniqueNodes`, которая удаляет дубликаты узлов, оставляя только первое вхождение:

```typescript
const uniqueNodes = useMemo(() => {
  const seen = new Set<string>();
  return nodes.filter((n) => {
    if (seen.has(n.id)) {
      console.warn(`Duplicate node found: ${n.id}. Keeping first occurrence.`);
      return false;
    }
    seen.add(n.id);
    return true;
  });
}, [nodes]);
```

### 2. Использование uniqueNodes везде

Все места, где использовался `nodes`, заменены на `uniqueNodes`:

- Создание карты `nodeById`
- Вычисление `ringRadii`
- Вычисление `rootNumbers`
- Рендеринг узлов

### 3. Дополнительная проверка в нумерации

В функции `rootNumbers` добавлена дополнительная проверка:

```typescript
const rootNodes = uniqueNodes.filter((n) => {
  return n.tier === "root" 
    && n.parentId === valueNode.id 
    && !processedRootIds.has(n.id); // Исключаем уже обработанные узлы
});
```

Это гарантирует, что каждый узел обрабатывается только один раз.

## Как это работает

1. **Удаление дубликатов**: При создании `uniqueNodes` мы проходим по всем узлам и добавляем их ID в Set `seen`. Если ID уже есть в Set, узел пропускается.

2. **Логирование**: Если обнаружен дубликат, выводится предупреждение в консоль:
   ```
   Duplicate node found: r-uptime. Keeping first occurrence.
   ```
   Это помогает отладить проблему и понять, откуда берутся дубликаты.

3. **Единообразие**: Все вычисления и рендеринг используют `uniqueNodes`, что гарантирует консистентность данных.

## Результат

✅ Узлы больше не дублируются  
✅ Каждый узел отображается только один раз  
✅ Цвет узла соответствует его ветке  
✅ Нумерация работает корректно  
✅ Логотип перекрашивается в правильный цвет  

## Производительность

- `useMemo` гарантирует, что фильтрация выполняется только при изменении `nodes`
- Set обеспечивает O(1) проверку наличия элемента
- Общая сложность: O(n), где n - количество узлов
- Минимальное влияние на производительность

## Отладка

Если проблема повторится, проверьте консоль браузера на наличие предупреждений:
```
Duplicate node found: <node-id>. Keeping first occurrence.
```

Это укажет на то, какие узлы дублируются, и поможет найти источник проблемы в данных или логике построения дерева.
