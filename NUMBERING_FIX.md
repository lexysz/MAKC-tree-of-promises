# Исправление проблемы с нумерацией корневых обещаний

## Проблема

Пользователь сообщил о двух проблемах с нумерацией корневых обещаний:

1. **Неправильный порядок**: После 3.4 идёт 5.3, затем 3.6
2. **Дублирование номеров**: 5.3 повторяется после 5.2, что приводит к перекраске логотипа в неправильный цвет

## Причина проблемы

В коде нумерации корневых обещаний (`src/components/TreeCanvas.tsx`) был баг:

```typescript
sortedRoots.forEach((rootNode, rootIndex) => {
  numbers.set(rootNode.id, `${valueIndex + 1}.${rootIndex + 1}`);
});
```

**Проблема**: Если один и тот же `rootNode.id` встречался несколько раз (например, из-за дублирования в данных или повторной обработки), то номер перезаписывался последним значением.

Это приводило к:
- Неправильному порядку нумерации (узлы получали номера в порядке их последней обработки)
- Дублированию номеров (несколько узлов могли получить один и тот же номер)
- Неправильному перекрашиванию логотипа (номер использовался для определения цвета)

## Решение

Добавлена проверка на дубликаты с использованием `Set`:

```typescript
const rootNumbers = useMemo(() => {
  const numbers = new Map<string, string>();
  const processedRootIds = new Set<string>(); // Отслеживаем уже обработанные узлы
  
  // ... код сортировки ...
  
  sortedRoots.forEach((rootNode, rootIndex) => {
    // Проверяем, что узел ещё не был обработан
    if (!processedRootIds.has(rootNode.id)) {
      processedRootIds.add(rootNode.id);
      numbers.set(rootNode.id, `${valueIndex + 1}.${rootIndex + 1}`);
    }
  });
  
  return numbers;
}, [nodes]);
```

## Как это работает

1. **Set `processedRootIds`**: Хранит ID всех уже обработанных корневых узлов
2. **Проверка перед обработкой**: `if (!processedRootIds.has(rootNode.id))`
3. **Добавление в Set**: `processedRootIds.add(rootNode.id)` после обработки
4. **Гарантия уникальности**: Каждый узел обрабатывается только один раз

## Результат

✅ Каждый корневой узел получает уникальный номер  
✅ Нумерация идёт в правильном порядке (по часовой стрелке от 12 часов)  
✅ Нет дублирования номеров  
✅ Логотип перекрашивается в правильный цвет ветки  
✅ Стабильная и предсказуемая нумерация

## Технические детали

### Почему использовался Set вместо проверки в Map?

**Set**:
- O(1) проверка наличия элемента
- O(1) добавление элемента
- Оптимизирован для хранения уникальных значений
- Меньше памяти, чем Map

**Map**:
- Хранит пары ключ-значение
- Нам нужно только отслеживать наличие ID, а не значения
- Set более семантически правильный для этой задачи

### Производительность

- Добавление в Set: O(1)
- Проверка наличия: O(1)
- Общая сложность: O(n), где n - количество корневых узлов
- Нет влияния на производительность при рендеринге

### Совместимость

- Set поддерживается во всех современных браузерах
- Не требует полифилов
- Работает в ES6+
