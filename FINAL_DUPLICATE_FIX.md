# Финальное исправление проблемы с дублированием узлов

## Проблема

Узел 3.5 привязывался к неправильной ценности (к которой должен был быть привязан узел 5.3), а узел 5.3 пропадал. При этом узел 3.5 отображался с неправильным цветом ветки.

## Корневая причина

Проблема была в `src/lib/excel.ts` в логике создания корневых обещаний:

```typescript
// СТАРЫЙ КОД (неправильный)
let root = rootsMap.get(rootTitle);
if (!root) {
  root = { ... };
  rootsMap.set(rootTitle, root);
  stats.roots++;
}

// Добавляем корневое обещание в ценность (даже если оно уже существует)
if (!value.promises.some(p => p.id === root!.id)) {
  value.promises.push(root);
}
```

**Проблема**: Если корневое обещание с таким `rootTitle` уже существовало в `rootsMap`, то оно добавлялось в `value.promises` текущей ценности. Это приводило к тому, что:

1. Одно и то же обещание могло принадлежать нескольким ценностям
2. В массиве `nodes` создавались дубликаты узлов с одинаковым `id`, но разными `parentId` и `color`
3. При создании карты `nodeById` последний узел перезаписывал первый
4. Узел отображался с неправильным цветом и привязывался к неправильной ценности

## Решение

### 1. Исправление в `excel.ts`

```typescript
// НОВЫЙ КОД (правильный)
let root = rootsMap.get(rootTitle);
if (!root) {
  root = { ... };
  rootsMap.set(rootTitle, root);
  stats.roots++;
  
  // Добавляем корневое обещание в ценность ТОЛЬКО при создании
  value.promises.push(root);
} else {
  // Если обещание уже существует, НЕ добавляем его в другую ценность
  console.warn(`Root promise "${rootTitle}" already exists in another value. Skipping.`);
}
```

**Что изменилось**:
- Корневое обещание добавляется в `value.promises` ТОЛЬКО при создании
- Если обещание уже существует в `rootsMap`, оно НЕ добавляется в другую ценность
- Каждое корневое обещание принадлежит только одной ценности (первой, где оно встретилось)

### 2. Добавление функции `uniqueNodes` в `TreeCanvas.tsx`

```typescript
// Удаляем дубликаты узлов, сохраняя первый встреченный
const uniqueNodes = useMemo(() => {
  const seen = new Map<string, GraphNode>();
  nodes.forEach((n) => {
    if (!seen.has(n.id)) {
      seen.set(n.id, n);
    } else {
      console.warn(`Duplicate node found: ${n.id}. Keeping first occurrence.`);
    }
  });
  return Array.from(seen.values());
}, [nodes]);
```

**Что это делает**:
- Проходит по всем узлам и сохраняет первый встреченный узел с каждым `id`
- Если обнаружен дубликат, выводит предупреждение в консоль
- Возвращает массив уникальных узлов

### 3. Использование `uniqueNodes` везде

Все места, где использовался `nodes`, заменены на `uniqueNodes`:

- Создание карты `nodeById`
- Вычисление `ringRadii`
- Вычисление `rootNumbers`
- Рендеринг узлов

✅ Узлы правильно привязываются к своим ценностям  
✅ Нумерация работает корректно (1.1, 1.2, 2.1, 2.2, 3.1...)

✅ Все узлы отображаются на дереве  

## Как это работает

### Сценарий 1: Обещание встречается один раз

```
Excel:
Ценность A | Обещание X | ...
Ценность B | Обещание Y | ...

Результат:
- Обещание X создаётся и добавляется в ценность A
- Обещание Y создаётся и добавляется в ценность B
- Нумерация: 1.1, 2.1
```

### Сценарий 2: Обещание встречается несколько раз

```
Excel:
Ценность A | Обещание X | ...
Ценность B | Обещание X | ...  ← Дубликат

Результат:
- Обещание X создаётся при первом появлении (в ценности A)
- При втором появлении (в ценности B) выводится предупреждение
- Обещание X НЕ добавляется в ценность B
- Нумерация: 1.1 (только в ценности A)
```

### Сценарий 3: Дубликаты в массиве nodes

```
nodes = [
  { id: "r-x", parentId: "v-a", color: "red" },
  { id: "r-x", parentId: "v-b", color: "blue" }  ← Дубликат
]

Результат:
- uniqueNodes удаляет дубликат
- Сохраняется первый узел: { id: "r-x", parentId: "v-a", color: "red" }
- Узел отображается с правильным цветом и привязкой
```

## Технические детали

### Почему каждое обещание должно принадлежать только одной ценности?

В структуре дерева обещаний каждое корневое обещание должно быть уникальным и принадлежать только одной ценности. Это гарантирует:

1. **Чёткую иерархию**: каждое обещание имеет одного родителя
2. **Корректную нумерацию**: номера не дублируются и не пересекаются
3. **Правильный цвет**: узел отображается с цветом своей ценности
4. **Отсутствие дубликатов**: каждый узел отображается только один раз

### Проверка дубликатов на разных уровнях

1. **`excel.ts`**: Проверка перед добавлением в `value.promises`
   ```typescript
   if (!root) {
     value.promises.push(root);
   } else {
     console.warn(`Root promise already exists`);
   }
   ```

2. **`TreeCanvas.tsx`**: Удаление дубликатов из массива `nodes`
   ```typescript
   const uniqueNodes = useMemo(() => {
     const seen = new Map<string, GraphNode>();
     nodes.forEach((n) => {
       if (!seen.has(n.id)) {
         seen.set(n.id, n);
       }
     });
     return Array.from(seen.values());
   }, [nodes]);
   ```

3. **`layout.ts`**: Проверка перед добавлением в массив `nodes`
   ```typescript
   if (!nodeIds.has(root.id)) {
     nodeIds.add(root.id);
     nodes.push(...);
   }
   ```

## Производительность

- Проверка в `excel.ts`: O(1) благодаря Map
- Функция `uniqueNodes`: O(n), где n - количество узлов
- `useMemo` гарантирует, что фильтрация выполняется только при изменении `nodes`
- Минимальное влияние на производительность

Если проблема повторится, проверьте:

1. **Консоль браузера**: Есть ли предупреждения о дубликатах
   ```

   ```

2. **Данные в `values`**: Правильно ли заполнен массив `promises` для каждой ценности
   ```javascript

   });
   ```

3. **Массив `nodes`**: Нет ли дубликатов узлов с одинаковым `id`
   ```javascript
   const ids = nodes.map(n => n.id);

   console.log('Duplicates:', duplicates);
   ```

   ```javascript

   ```
